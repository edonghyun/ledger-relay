Full reconciliation
Checks every completed command, from the first one, against its transfer in TigerBeetle and lists any command that does not match. The Consistency panel at the bottom shows only the totals of the same reconciliation, refreshed every second.
Scenariosbreak it on purpose
Scenario controls are available only with the demo profile.
① Normal payment
Pay in the Store → Authorized (the buyer's money is held) → Ship → Paid (the money moves to the merchant).
② TigerBeetle connection
Cut it: orders are still accepted and the backlog grows. Restore it: the backlog drains, each command once, and Consistency stays green.
③ Inject a bad post
A post with an earlier sequence number than its reservation → only that order halts, the rest keep flowing. Abandon it in the Operator tab and the order ends as Cancelled.
④ Double click
Sends two payment requests with the same Idempotency-Key at the same time. The result must be one order and one reservation.
⑤ Cancel before shipping
Cancel an authorized order → the reservation is voided and the held money is released.
Burst of 50 orders
Places orders from several buyers at once, each on its own ordering key. The two workers split the work and never claim the same command (see the per-instance sent counts in the Store tab).
